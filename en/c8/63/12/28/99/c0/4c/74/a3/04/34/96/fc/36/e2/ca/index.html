How to Undo the Last Commit

By @danny · Tutorial

You committed, closed the tab and thirty seconds later you realized: a file was missing, the message came out wrong or you slipped in a change that didn't belong. If that sounds familiar, relax, it's everyday stuff, and the good news is that undoing the last commit is one of git's easiest operations; with three or four well-understood commands you'll fix it in seconds.

First: where the changes live

Before getting into the commands, it's worth being clear that in git a change travels through three places: the working area (your files as they are), the staging (what you marked with git add) and the commit (the snapshot saved in the history). Undoing a commit is nothing more than moving changes between those three zones depending on what you need.

A single golden rule: if you already published the commit with git push and you work with other people, don't rewrite the history and jump straight to the section on git revert at the end.

The wildcard: git reset

The main tool for this is git reset: it moves the HEAD pointer backward (with HEAD~1 you go back one commit) and lets you decide what to do with the changes depending on the mode. You have three modes available:

  • --soft: reverts the commit and leaves the changes waiting in the staging area, ready to commit again, you lose nothing.
  • --mixed (the default mode): the changes leave the staging area and remain as plain modifications in your working area, you don't lose anything either.
  • --hard: discards the commit and its changes completely, powerful but with no way back.

I got the message wrong or a file was missing

It's the most common case: the commit is the last one, it hasn't been published yet and you want to fix it without dirtying the history. The shortest way is git commit --amend, which rewrites the last commit, whether just to fix the message or after adding the file that was missing:

git commit --amend -m "Corrected message"
git add missing-file.js
git commit --amend

And if what you want is to redo the commit from scratch to change what it included, git reset comes in with the mode that suits you best: use --soft if you want everything ready to commit again:

git reset --soft HEAD~1

or --mixed if you prefer the changes to go back to your working area as pending edits:

git reset HEAD~1

In either case the commit disappears from the history, but your changes stay safe.

I want to remove the commit and its changes

For the extreme case there's git reset --hard, which discards the commit and also the changes it carried:

git reset --hard HEAD~1

Check twice before running it, because if that change isn't committed anywhere else (not even on another branch) it's lost forever; when in doubt, prefer --soft or --mixed, which destroy nothing.

If the commit has already been published

This applies especially to teamwork: you already pushed and now you have to undo it. In that case we don't use reset, because rewriting the history breaks the repo for everyone else; the correct tool is git revert, which instead of deleting anything creates a new commit that reverses the changes of the previous one:

git revert HEAD
git revert <commit-hash>

The history stays clean and transparent: anyone can see that there was a commit and then its correction, and that's why it's the safe option when the change has already been shared.
