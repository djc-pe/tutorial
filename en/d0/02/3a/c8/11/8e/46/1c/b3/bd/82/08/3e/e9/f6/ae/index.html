How to Make a Triangle in C++: Asterisks, Pyramid and Sierpinski

Series by @null_djc

  • C++
  • Programming
  • Beginners

The asterisk triangle is the first loop exercise of almost any course, and in C++ it is also the first one many people solve on a judge like Codeforces. C++ warns you about almost nothing: if something goes wrong, the program carries on as if nothing happened. Here we look at where those mistakes hide and how to get the compiler to help you.

We cover it in three levels: basic (the triangle and its traps), intermediate (the pyramid and its variants) and advanced (Pascal, Sierpinski and the parentheses trap). Each level ends with a challenge. To try the code: g++ -std=c++17 -Wall triangle.cpp -o triangle && ./triangle.

Play with the triangle

Basic: the triangle and its traps

The triangle with one loop

Row 1 has one asterisk, row 2 has two, row 3 has three: the row and the count are the same number.

#include <iostream>
#include <string>

int main() {
    int n = 5;
    for (int i = 1; i <= n; i++) {
        std::cout << std::string(i, '*') << "\n";
    }
}

  • for (int i = 1; i <= n; i++) counts from 1 to 5: it starts at 1, keeps going while i is less than or equal to 5 and adds 1 on each pass.
  • std::string(i, '*') creates a text with i asterisks. The count goes first and then the character, in single quotes.
  • "\n" jumps to a new line. It is preferred over std::endl, which also flushes the output and makes the program slower when it prints a lot.

The trap: the missing row

Out of habit, many C++ loops start at 0 and use <. Here that breaks the triangle:

#include <iostream>
#include <string>

int main() {
    int n = 5;
    for (int i = 0; i < n; i++) {
        std::cout << std::string(i, '*') << "\n";
    }
}

There is an empty line at the top (std::string(0, '*') is empty text) and the row of five is missing, because i < n stops at 4. When the result has one row too many or too few, check where the loop starts and whether the condition is < or <=.

Upside down

For the inverted triangle, the loop starts at n and subtracts 1 (i--):

#include <string>

int main() {
    int n = 5;
    for (int i = n; i >= 1; i--) {
        std::cout << std::string(i, '*') << "\n";
    }
}

Let the user choose the size

And if the user types hello? C++ gives no error at all: cin fails silently, n stays at 0, the loop does not run even once and the program ends without printing anything. To notice, check whether the read worked:

#include <iostream>
#include <string>

int main() {
    int n;
    if (!(std::cin >> n)) {
        std::cout << "That is not a number\n";
        return 1;
    }
    for (int i = 1; i <= n; i++) {
        std::cout << std::string(i, '*') << "\n";
    }
}

With two loops

Without std::string(i, '*'), the row is printed with a loop inside another: the outer one goes through the rows and the inner one prints one asterisk per pass.

#include <iostream>

int main() {
    int n = 4;
    for (int i = 1; i <= n; i++) {
        for (int j = 0; j < i; j++) {
            std::cout << '*';
        }
        std::cout << "\n";
    }
}

Intermediate: the pyramid and its variants

Right-aligned

Each row starts with n - i spaces, so the triangle sits against the right:

#include <iostream>
#include <string>

int main() {
    int n = 5;
    for (int i = 1; i <= n; i++) {
        std::cout << std::string(n - i, ' ') << std::string(i, '*') << "\n";

}

The pyramid

The pyramid grows by two asterisks per row (1, 3, 5, 7, 9) so it has a center: 2 * i - 1 asterisks and n - i spaces.

#include <iostream>
#include <string>

int main() {
    int n = 5;
    for (int i = 1; i <= n; i++) {
        std::cout << std::string(n - i, ' ') << std::string(2 * i - 1, '*') << "\n";
    }
}

This table is the trick for any pattern: write down by hand how much goes in each row and look for the formula. If the pyramid comes out crooked, the spaces are almost always n - i - 1 or the asterisks 2 * i.

Hollow

Only the border: the first row with one asterisk, the last one full and the middle ones with an asterisk on each side and 2 * i - 3 spaces in the center.

#include <iostream>
#include <string>

int main() {
    int n = 5;
    for (int i = 1; i <= n; i++) {
        if (i == 1) {
            std::cout << std::string(n - 1, ' ') << "*\n";
        } else if (i == n) {
            std::cout << std::string(2 * n - 1, '*') << "\n";
        } else {
            std::cout << std::string(n - i, ' ') << "*" << std::string(2 * i - 3, ' ') << "*\n";
        }
    }
}

With numbers

Each row counts from 1 to the row number, with a space between numbers (but not before the first one, hence the if (j > 1)):

#include <iostream>
#include <string>

int main() {
    int n = 5;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= i; j++) {
            if (j > 1) std::cout << " ";
            std::cout << j;
        }
        std::cout << "\n";
    }
}

The order trap in std::string

std::string(3, '*') is three asterisks. The other way around, std::string('*', 3) compiles without complaint, because a character is also a number ('*' is 42):

#include <iostream>
#include <string>

int main() {
    std::string row('*', 3);
    std::cout << row.size() << "\n";
}
42

That is 42 invisible characters (character number 3). On screen it looks like nothing was printed, but a judge marks it as wrong.

Advanced: Pascal, Sierpinski and the parentheses

Pascal's triangle

Each number is the sum of the two on top of it, and the borders are 1. Each row is built from the previous one, in a std::vector:

#include <iostream>
#include <string>
#include <vector>

int main() {
    int n = 5;
    std::vector<long long> row = {1};
    for (int i = 0; i < n; i++) {
        std::cout << std::string(n - i - 1, ' ');
        for (size_t k = 0; k < row.size(); k++) {
            if (k > 0) std::cout << " ";
            std::cout << row[k];
        }
        std::cout << "\n";
        std::vector<long long> next = {1};
        for (size_t k = 0; k + 1 < row.size(); k++) {
            next.push_back(row[k] + row[k + 1]);
        }
        next.push_back(1);
        row = next;
    }
}

   1 1
  1 2 1
 1 3 3 1
1 4 6 4 1

A long long goes up to 9223372036854775807. With n of 68 or more, the numbers in the center no longer fit, and C++ does not warn you: the result is a wrong number (technically, undefined behavior). With unsigned long long you gain one more row; for bigger rows you need big integers.

Sierpinski with asterisks

If you only paint the odd numbers of Pascal's triangle, the Sierpinski triangle appears. The number in row i and position j is odd when (j & i) == j:

#include <iostream>
#include <string>

int main() {
    int n = 8;
    for (int i = 0; i < n; i++) {
        std::cout << std::string(n - i - 1, ' ');
        for (int j = 0; j <= i; j++) {
            if (j > 0) std::cout << " ";
            std::cout << ((j & i) == j ? "*" : " ");
        }
        std::cout << "\n";
    }
}

The parentheses trap

In C++, == is evaluated before &. Without parentheses, j & i == j is j & (i == j), and the drawing breaks:

#include <iostream>
#include <string>

int main() {
    int n = 8;
    for (int i = 0; i < n; i++) {
        std::cout << std::string(n - i - 1, ' ');
        for (int j = 0; j <= i; j++) {
            if (j > 0) std::cout << " ";
            std::cout << (j & i == j ? "*" : " ");
        }
        std::cout << "\n";
    }
}

That is why we compile with -Wall: with that option, g++ warns exactly about this.

warning: suggest parentheses around comparison in operand of ‘&’ [-Wparentheses]

A warning does not stop the compilation, so it is easy to miss. Get used to compiling with -Wall and reading what it says before running.

What it taught us

That the triangle is a table (how many spaces and how many asterisks in each row), just like in any language, and that in C++ the most expensive mistakes are the quiet ones: the cin that fails without warning, the std::string with its arguments swapped, the number that does not fit and the operator that is evaluated first. Always compile with -Wall: many of those traps are a warning the compiler was already giving you.
