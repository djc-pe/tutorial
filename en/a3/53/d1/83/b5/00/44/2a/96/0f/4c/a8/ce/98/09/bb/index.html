Problem #1: SauSaGe Bank

By @null_djc · Series

Codeforces 2269A · Div. 2 · greedy, math

The simplified statement

A bank doubles your balance every morning, and at night you can withdraw everything: what you withdraw is added to your card and your account goes back to $1 to start over. The bank lasts exactly n days and you have to withdraw on exactly k days. The question is simple: what's the most you can collect on your card?

The trap

The first thing we thought was "if I withdraw on day d, I get 2^d". And that's a mistake, because after each withdrawal the balance resets to $1. Notice what happens if you withdraw on day 3 and again on day 4: on day 4 there was only one doubling, so you only get $2. What you get on a withdrawal is 2 raised to the number of days since the last withdrawal, not since the starting day.

The idea

Since you have to withdraw k times, you end up splitting the n days into k blocks, and each block ends on the day you withdraw. If a block has g days, that withdrawal gives you 2^g. Since 2^x grows extremely fast, it's best to concentrate almost everything in a single long block and make the others as short as possible (one day, which gives $2 each).

The formula

answer = 2^(n - k + 1) + 2 * (k - 1)

The long block leaves you n - k + 1 days (and with that you earn the big part), and the remaining k - 1 withdrawals contribute $2 each. Since n ≤ 30, 2^30 fits comfortably in a long long.

The solution

In the problem's test cases, the rule doesn't fail: (1,1) → 2, (2,1) → 4, (4,3) → 8, (5,5) → 10, (10,2) → 514. We turn the statement into code, with a bit shift:

C++

#include <iostream>
using namespace std;

int main() {
    int t;
    cin >> t;

    while (t--) {
        int n, k;
        cin >> n >> k;

        cout << (1LL << (n - k + 1)) + 2LL * (k - 1) << '\n';
    }

    return 0;
}

Python

t = int(input())

for _ in range(t):
    n, k = map(int, input().split())
    print((1 << (n - k + 1)) + 2 * (k - 1))

Rust

use std::io::{self, Read};

fn main() {
    let mut input = String::new();
    io::stdin().read_to_string(&mut input).unwrap();

    let mut it = input.split_whitespace();

    let t: usize = it.next().unwrap().parse().unwrap();

    for _ in 0..t {
        let n: u32 = it.next().unwrap().parse().unwrap();
        let k: i64 = it.next().unwrap().parse().unwrap();

        let answer = (1_i64 << (n - k as u32 + 1))
            + 2 * (k - 1);

        println!("{}", answer);
    }
}

What it taught us

To read carefully the effect of each event and the order in which they happen: the "reset" of the balance was the whole problem. And to play with the examples by hand before opening the editor, because that's where the pattern appeared that later became a formula.
