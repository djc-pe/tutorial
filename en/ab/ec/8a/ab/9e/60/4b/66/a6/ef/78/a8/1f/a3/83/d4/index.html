What Is Software Development?

By @danny · Tutorial

If you're just starting out, you've surely heard the term a thousand times: software development, "making programs". In simple words, it's the process of creating a program: defining what it will do, designing how, writing the code, testing it, shipping it and then maintaining it. And no, it's not just writing code.

From idea to program

It all starts with a problem or an idea. It could be "I want my customers to pay online" or "I want to organize my notes". At that stage not a single line of code is written: you talk to people, write down requirements and define what you want to achieve. This is followed by design: how the screens will look, how the information is structured in the database, which parts communicate with which.

Only then does the part everyone imagines appear: programming. Fighting with the keyboard, hunting down that error nobody knows why happens, and celebrating when it finally works. But careful, it doesn't end there. Software has to be tested before you release it, because a bug in production hurts. And then, maintain it: fix what breaks, improve what already exists and add new features.

The software life cycle (SDLC)

This process from start to finish is called the software development life cycle (or SDLC). It's not a religion, it's just a way to organize the work:

  1. Planning: what will be done, with how many people and in how much time.
  2. Requirements: asking the client or user what they really need.
  3. Design: drawing the blueprint: architecture, screens, database.
  4. Implementation: writing the actual code.
  5. Testing: looking for ways it breaks before users do.
  6. Deployment: getting it running in the production environment.
  7. Maintenance: keeping it alive: updates, bugs, improvements.

Not all projects go through these phases in this order. Sometimes you start with an ugly prototype just to validate the idea, and polish it as you go.

Types of software

Software is usually divided into two big groups. System software is the one underneath, the one that holds everything up: the operating system, drivers, utilities. Without it, nothing else works. And application software is what we interact with daily: browsers, banking apps, games, work tools.

If you'd never seen it that way, think in layers: the operating system is the base, and on top of it sit the applications we use every day.

How is the work organized?

Here enters the eternal debate about methodologies. The classic way was the waterfall model: everything ordered, one phase after another, like a production line. It sounds neat, but if the client changes their mind halfway through the project (and they always do), it gets complicated.

That's why today agile methodologies rule (Scrum, Kanban): you work in short cycles, deliver something functional every two or three weeks and adjust based on what the user says. And if the team also does DevOps, deployments get automated, so what you develop reaches production almost without friction.

Who works on a project

Contrary to the idea that programming is a solitary job, there's almost always a team behind it:

  • Developers: frontend (what you see), backend (what you don't), full-stack (both).
  • UX/UI designer: making the product understandable and good-looking.
  • QA: the ones in charge of breaking the software on purpose so it holds up.
  • Product Manager or analyst: the bridge between the business and the code.
  • DevOps: making sure everything deploys and works without drama.

In small teams one person does all of this at once. And that's fine.

To wrap up

Software development isn't magic and it's not just sitting down to type. It's solving problems with method, surrounded by people and constantly learning. If you're just starting, don't get scared by the endless list of technologies: learn the fundamentals, build small things and fail fast. That's how you get to do it well.
