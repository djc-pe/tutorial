How to Make a Triangle in Rust: Asterisks, Pyramid and Sierpinski

Series by @null_djc

  • Rust
  • Programming
  • Beginners

The asterisk triangle is the first loop exercise of almost any course. In Rust it is written much like Python, but the compiler watches out for things that happen silently in other languages: a number that cannot be read, a subtraction that goes below zero or a sum that does not fit. Here we look at those traps with their real messages.

We cover it in three levels: basic (the triangle and its traps), intermediate (the pyramid and its variants) and advanced (formatting, Pascal and Sierpinski). Each level ends with a challenge. To try the code: rustc triangle.rs && ./triangle, cargo run inside a project, or the Rust Playground in the browser.

Basic: the triangle and its traps

The triangle with one loop

Row 1 has one asterisk, row 2 has two, row 3 has three: the row and the count are the same number.

fn main() {
    let n = 5;
    for i in 1..=n {
        println!("{}", "*".repeat(i));
    }
}

  • 1..=n is the range from 1 to 5, including the 5 (because of the =).
  • "*".repeat(i) repeats the text: "*".repeat(3) is "***".
  • println! prints and jumps to a new line; the {} is where the value goes.

The trap: the missing row

Rust has two ranges that look very much alike: 0..n does not include the last one and 0..=n does. With the first one, the triangle comes out wrong:

fn main() {
    let n = 5;
    for i in 0..n {
        println!("{}", "*".repeat(i));
    }
}

There is an empty line at the top ("*".repeat(0) is empty text) and the row of five is missing. When the result has one row too many or too few, check the range first: where it starts and whether it has an =.

Upside down

For the inverted triangle, the range is walked backwards with .rev():

fn main() {
    let n = 5;
    for i in (1..=n).rev() {
        println!("{}", "*".repeat(i));
    }
}

Let the user choose the size

The size is read from the input as text and turned into a number with parse. Typing 3:

use std::io;

fn main() {
    let mut line = String::new();
    io::stdin().read_line(&mut line).unwrap();
    let n: usize = line.trim().parse().unwrap();
    for i in 1..=n {
        println!("{}", "*".repeat(i));
    }
}
*
**
***

The trim() is the trap: read_line also keeps the line break from the Enter key ("3\n"), and that \n is not a digit. Without trim(), the program stops with this message:

called `Result::unwrap()` on an `Err` value: ParseIntError { kind: InvalidDigit }

It is the same message you get if the user types hello. unwrap() says "if it fails, stop the program"; to warn the user instead of stopping, you use match on the result of parse.

With two loops

repeat is a shortcut. Without it, you use a loop inside another: the outer one goes through the rows and the inner one prints the asterisks with print!, which does not jump to a new line. The empty println!() jumps when the row is done.

fn main() {
    let n = 4;
    for i in 1..=n {
        for _ in 0..i {
            print!("*");
        }
        println!();
    }
}

Intermediate: the pyramid and its variants

Right-aligned

Each row starts with n - i spaces, so the triangle sits against the right:

fn main() {
    let n = 5;
    for i in 1..=n {
        println!("{}{}", " ".repeat(n - i), "*".repeat(i));
    }
}

The pyramid

The pyramid grows by two asterisks per row (1, 3, 5, 7, 9) so it has a center: 2 * i - 1 asterisks and n - i spaces.

This table is the trick for any pattern: write down by hand how much goes in each row and look for the formula. If the pyramid comes out crooked, the spaces are almost always n - i - 1 or the asterisks 2 * i.

Hollow

Only the border: the first row with one asterisk, the last one full and the middle ones with an asterisk on each side and 2 * i - 3 spaces in the center.

fn main() {
    let n = 5;
    for i in 1..=n {
        if i == 1 {
            println!("{}*", " ".repeat(n - 1));
        } else if i == n {
            println!("{}", "*".repeat(2 * n - 1));
        } else {
            println!("{}*{}*", " ".repeat(n - i), " ".repeat(2 * i - 3));
        }
    }
}

With numbers

Each row counts from 1 to the row number. map turns each number into text, collect gathers them into a Vec and join(" ") joins them with spaces:

fn main() {
    let n = 5;
    for i in 1..=n {
        let nums: Vec<String> = (1..=i).map(|j| j.to_string()).collect();
        println!("{}", nums.join(" "));
    }
}

Advanced: formatting, Pascal and Sierpinski

Let formatting do the work

println! knows how to align: {:>width$} aligns to the right within a width and {:^width$} centers. That way there is no need to work out spaces:

fn main() {
    let n = 5;
    for i in 1..=n {
        println!("{:>width$}", "*".repeat(i), width = n);
    }
}

When centering, the formatting also adds spaces on the right. You cannot see them, but a judge like Codeforces' counts them; trim_end() removes them.

The subtraction that goes below zero

Sizes in Rust are usize: unsigned numbers, which cannot be negative. If the loop runs one time too many, n - i - 1 tries to go below zero and the program stops:

fn main() {
    let n = 5;
    for i in 0..=n {
        println!("{}{}", " ".repeat(n - i - 1), "*".repeat(2 * i + 1));
    }
}

In other languages that subtraction would give a negative number and the mistake would stay hidden. Here the message says exactly what happened: the range had to be 0..n.

Pascal's triangle

Each number is the sum of the two on top of it, and the borders are 1. Each row is built from the previous one:

fn main() {
    let n = 5;
    let mut row: Vec<u64> = vec![1];
    for i in 0..n {
        let text: Vec<String> = row.iter().map(|x| x.to_string()).collect();
        println!("{}{}", " ".repeat(n - i - 1), text.join(" "));
        let mut next = vec![1];
        for k in 0..row.len() - 1 {
            next.push(row[k] + row[k + 1]);
        }
        next.push(1);
        row = next;
    }
}

1 4 6 4 1

A u64 goes up to 18446744073709551615. With n of 68 or more, one of the sums no longer fits: with rustc (or cargo run) the program stops with

attempt to add with overflow

but compiled with optimizations (-O or cargo run --release) that check is turned off and the sum wraps around silently: with n = 70, the number in the center of the last row comes out as 1505813374405535736, which is wrong. For rows that big you use u128 or a big integer library.

Sierpinski with asterisks

If you only paint the odd numbers of Pascal's triangle, the Sierpinski triangle appears. The number in row i and position j is odd when (j & i) == j:

fn main() {
    let n = 8;
    for i in 0..n {
        let row: Vec<&str> = (0..=i).map(|j| if (j & i) == j { "*" } else { " " }).collect();
        println!("{}{}", " ".repeat(n - i - 1), row.join(" "));
    }
}

In Rust, as in Python, & is evaluated before ==, so it would work without parentheses. We keep them anyway: in JavaScript and C++ it is the other way around, and this way the code reads the same everywhere.

What it taught us

That the triangle is a table (how many spaces and how many asterisks in each row), just like in any language, and that Rust turns hidden mistakes into clear messages: the line break that keeps the number from being read, the subtraction that goes below zero, the sum that does not fit. It is annoying at first, but each of those messages is a mistake you would have hunted for blindly in another language.
