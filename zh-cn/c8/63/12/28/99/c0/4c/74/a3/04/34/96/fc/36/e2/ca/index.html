如何撤销最后一次提交？

作者 @danny · 教程

你提交了、关掉了标签页，三十秒后才发现：漏了一个文件、提交信息写错了，或者混进了一个不该有的改动。如果觉得眼熟，别急，这再正常不过，而且好消息是：撤销最后一次提交是 git 里最简单的操作之一；用三四条真正理解了的命令，几秒钟就能搞定。

首先：改动存在于哪里

在进入命令之前，最好先弄清楚：在 git 里，一个改动会经历三个地方：工作区（你现在的文件）、暂存区（你用 git add 标记的内容）和提交（保存在历史里的快照）。撤销提交，无非是按你的需要在三个区域之间移动改动。

一条黄金法则：如果这个提交你已经用 git push 发布过了，而且你在和别人协作，就不要改写历史，直接跳到最后关于 git revert 的那一节。

万能工具：git reset

做这件事的主要工具是 git reset：它把 HEAD 指针往回移（用 HEAD~1 就回退一个提交），并让你根据模式决定如何处理改动。你有三种模式：

  • --soft：回退提交，把改动留在暂存区里等你重新提交，什么都不会丢。
  • --mixed（默认模式）：改动离开暂存区，变成工作区里的普通修改，同样什么都不会丢。
  • --hard：彻底丢弃提交及其改动，很强但无法回头。

提交信息写错了，或者漏了一个文件

这是最常见的情况：提交就是最后一个、还没发布，你想在不弄脏历史的情况下修正它。最短的办法是 git commit --amend，它会重写最后一个提交，既可以只是修改提交信息，也可以在补上遗漏的文件之后使用：

git commit --amend -m "修正后的信息"
git add 遗漏的文件.js
git commit --amend

如果你想从零重做这个提交、改变它所包含的内容，那就用 git reset，选最适合你的模式：如果你希望一切就绪、可以直接重新提交，就用 --soft：

git reset --soft HEAD~1

或者用 --mixed，如果你更希望改动回到工作区作为待处理的编辑：

git reset HEAD~1

无论哪种情况，提交都会从历史里消失，但你的改动都安然无恙。

我想删除这个提交及其改动

极端情况下有 git reset --hard，它会丢弃提交以及它带来的改动：

git reset --hard HEAD~1

执行前请再三确认，因为这个改动如果在别处都没被提交过（甚至不在其他分支上），就会永远丢失；拿不准时，优先用 --soft 或 --mixed，它们不会破坏任何东西。

如果提交已经发布

这尤其适用于团队协作：你已经 push 了，现在要撤销它。这种情况下我们不用 reset，因为改写历史会弄坏其他人的仓库；正确的工具是 git revert，它不删除任何东西，而是创建一个新提交来反转上一个提交的改动：

git revert HEAD
git revert <commit-hash>

历史保持干净透明：任何人都能看到曾经有一个提交，然后是它的修正，所以当改动已经共享出去时，它是安全的选择。
