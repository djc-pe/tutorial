深度优先搜索（DFS）

作者：@null_djc（教程）

如果你解过和图、迷宫或网格地图有关的题，一定见过这三个字母：DFS。它是 Depth-First Search（深度优先搜索）的缩写，是那种到处都会出现的工具：面试里、Codeforces 上，以及一半需要“把某个东西走一遍”的题目里。

它的思路一句话就能说完：沿着一条路尽量往前走，走到无路可走时，就退回去换另一条路。

用一个例子理解

想象一个迷宫。你选一条走廊，一直走到尽头。如果碰到死路，就回到上一个岔口，试一条还没走过的走廊。就这样，直到把所有地方都看过。

为了不绕圈子，你在每个经过的地方做个记号。有了这一点，整个算法就齐了：

  1. 把当前节点标记为已访问。
  2. 对每个还没访问过的邻居，从那个邻居开始做 DFS。
  3. 当没有未访问的邻居时，回到上一个节点。这叫做回溯（backtracking）。

我们要用的图

我们取一个有 6 个节点的无向图，边是：1-2、1-3、2-4、2-5、3-6 和 5-6。我们把它存成邻接表：每个节点对应它的邻居列表。

1: 2, 3
2: 1, 4, 5
3: 1, 6
4: 2
5: 2, 6
6: 3, 5

我们从节点 1 出发，按列表顺序查看邻居。

陷阱

我们最先想到的是：“从 1 开始，接着访问它的邻居 2 和 3，然后再访问它们的邻居”。不对，那是另一个算法（BFS，广度优先搜索）。DFS 不会先把 1 的邻居都处理完：一旦发现新的邻居，就马上沿着它一路走到底。

看看真正的走法：

  1. 访问 1。它的第一个未访问邻居是 2：走进去。
  2. 访问 2。1 已经标记过，所以往下走到 4。
  3. 访问 4。它唯一的邻居 2 已经标记过：死路，退回 2。
  4. 从 2 出发还剩 5。访问它。
  5. 从 5 出发，2 已经标记过；继续走到 6。
  6. 从 6 到达 3。它的邻居（1 和 6）都已标记，于是一路退回起点。

顺序是 1, 2, 4, 5, 6, 3。3 是 1 的直接邻居，却排在最后，因为我们是在长路径的末尾从 6 走到它的。这就是“深度”。

递归解法

最自然的写法是递归：调用栈会自动记住要回到哪个节点。三个版本输出的顺序都和我们手算的一样。

C++

#include <iostream>
#include <vector>
using namespace std;

vector<vector<int>> graph;
vector<bool> visited;

void dfs(int node) {
    visited[node] = true;
    cout << node << ' ';
    for (int neighbor : graph[node]) {
        if (!visited[neighbor]) dfs(neighbor);
    }
}

int main() {
    int n = 6;
    graph.assign(n + 1, {});
    visited.assign(n + 1, false);
    int edges[][2] = {{1, 2}, {1, 3}, {2, 4}, {2, 5}, {3, 6}, {5, 6}};
    for (auto& a : edges) {
        graph[a[0]].push_back(a[1]);
        graph[a[1]].push_back(a[0]);
    }
    dfs(1);  // 1 2 4 5 6 3
}

Python

graph = {
    1: [2, 3],
    2: [1, 4, 5],
    3: [1, 6],
    4: [2],
    5: [2, 6],
    6: [3, 5],
}

visited = set()
order = []

def dfs(node):
    visited.add(node)
    order.append(node)
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(neighbor)

dfs(1)
print(order)  # [1, 2, 4, 5, 6, 3]

Rust

fn dfs(node: usize, graph: &Vec<Vec<usize>>, visited: &mut Vec<bool>, order: &mut Vec<usize>) {
    visited[node] = true;
    order.push(node);
    for &neighbor in &graph[node] {
        if !visited[neighbor] {
            dfs(neighbor, graph, visited, order);
        }
    }
}

fn main() {
    let n = 6;
    let edges = [(1, 2), (1, 3), (2, 4), (2, 5), (3, 6), (5, 6)];

    let mut graph = vec![Vec::new(); n + 1];
    for &(a, b) in &edges {
        graph[a].push(b);
        graph[b].push(a);
    }

    let mut visited = vec![false; n + 1];
    let mut order = Vec::new();
    dfs(1, &graph, &mut visited, &mut order);

    println!("{:?}", order); // [1, 2, 4, 5, 6, 3]
}

不用递归：用一个栈

图很大时，递归可能会把调用栈撑爆。在 Python 里这很快就会发生，因为默认的递归深度上限大约是 1000 层。解决办法是自己管理这个栈：

def dfs_iterative(start):
    visited = set()
    order = []
    stack = [start]
    while stack:
        node = stack.pop()
        if node in visited:
            continue
        visited.add(node)
        order.append(node)
        for neighbor in reversed(graph[node]):
            if neighbor not in visited:
                stack.append(neighbor)
    return order

print(dfs_iterative(1))  # [1, 2, 4, 5, 6, 3]

有两个细节让我们踩过坑：邻居要倒序压栈（reversed），这样出栈的顺序才和递归版本一致；节点要在出栈时标记，而不是入栈时。一个节点可能多次进栈，但只在第一次出栈时处理。

它有多快？

每个节点只访问一次，每条边从两端各检查一次。设有 V 个节点、E 条边，时间复杂度是 O(V + E)，额外空间是 O(V)。也就是线性的：即使有几十万个节点，也能轻松满足任何评测系统的时间限制。

它能用来做什么

  • 判断两个节点是否连通：从其中一个做 DFS，看看能不能走到另一个。
  • 统计连通分量：遍历所有节点，每遇到一个未标记的节点，就启动一次 DFS，并把计数加一。
  • 检测环：如果遍历中走到了一个还在“进行中”的节点，就说明有环。
  • 拓扑排序：给相互依赖的任务排序，比如哪些课程要先修。
  • 网格问题：统计矩阵中的岛屿、填充一片区域（flood fill）或者走迷宫。

需要注意的地方

  • 忘记标记：如果图里有环，程序永远不会结束。
  • 递归版本里标记太晚：一进入 dfs 就标记节点，再去看邻居。
  • Python 的栈：图很大时，用迭代版本，或者用 sys.setrecursionlimit 提高上限。
  • 用它求最短路径：DFS 找到的是一条路径，不一定是最短的。在无权图里求最短路径要用 BFS。

我们学到了什么

DFS 代码不多，用处很大：一路走到底，标记看过的地方，无路可走时就回头。理解它最好的办法，是先像上面那样手动走一遍，再打开编辑器。然后凭记忆把它写出来，先写递归版，再写栈的版本，最后到真实的题目里去找它：在 Codeforces 上可以按 dfs and similar 标签筛选题目。
