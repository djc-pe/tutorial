如何用 SSH 从任何地方连接家里的电脑

作者：@null_djc（教程）

如果你曾经想在公司或者在外面连回家里的电脑，大概也碰到过和我们一样的问题：家里没有固定的公网 IP，路由器也不让任何人进来。解决办法是用一台在互联网上的服务器作跳板（也叫 jump host 或堡垒机），并且让家里的电脑主动连到它。

只要两条命令：在家里用 ssh -R 向跳板打开一条隧道，在外面用 ssh -J 从这条隧道进来。下面我们来看它为什么可行、怎么让它自己一直运行，以及我们一开始错在哪里。

用一个例子说明

我们有三台机器：

  • 家里的电脑，也就是目标。它在路由器后面，没有公网 IP，用户名是 ana。
  • 跳板，jump.example.com：一台在互联网上的服务器（随便一台 VPS），有公网 IP 和 SSH。
  • 公司的电脑，或者你在外面的笔记本：你想从这里连回家。

我们想要的是：在公司输入 ssh home，就直接进入家里的电脑，就像它就在旁边一样。

陷阱

我们最先想到的是最直接的办法：在路由器上开放 22 端口（端口转发），然后直接连家里的 IP。这样做有三个问题：

  1. 很多时候根本做不到。不少运营商让很多用户共用同一个公网 IP（CGNAT），你的路由器没有自己的 IP 可以开放。
  2. IP 会变。就算有公网 IP，也很少是固定的：今天一个，明天另一个，还得配置动态 DNS 去跟踪它。
  3. 你的家会暴露在整个互联网上。开放的 22 端口会日夜不停地收到机器人的登录尝试。

思路

路由器不让外面进来，但允许里面出去。所以我们反过来做：让家里的电脑连到跳板，并告诉它"打开你的 2222 端口，到那里的东西都转给我"。这就是反向隧道（-R）。

在公司，你连到跳板，请它把你接到它的 2222 端口，另一头就是你家。这条路上跑的是一条在公司和家之间端到端加密的 SSH 连接：跳板只负责转发它读不懂的字节。

这里有两条连接，每条连接的密钥分法都一样：私钥留在发起连接的机器上，公钥放在被连接的机器的 ~/.ssh/authorized_keys 里。

连接谁发起（私钥）连到哪里（公钥）
隧道家里的电脑跳板
跳转公司的电脑跳板
进入家里公司的电脑家里的电脑

没有任何私钥会经过跳板。

解决方法

1. 准备家里的电脑

家里的电脑需要一个 SSH 服务器，别人才能连进来；还需要一把密钥，用来连接跳板。在 Ubuntu 或 Debian 上：

sudo apt install openssh-server
ssh-keygen -t ed25519

公钥保存在 ~/.ssh/id_ed25519.pub。在公司的电脑上也用 ssh-keygen 生成一把，把它的公钥放进家里电脑的 ~/.ssh/authorized_keys。这一步要在家的时候做。

2. 在跳板上建一个只用于隧道的用户

在跳板上我们另建一个用户 tunnel，免得和你管理服务器用的用户混在一起：

sudo adduser --disabled-password tunnel

它的 /home/tunnel/.ssh/authorized_keys 里放两把公钥，每把只能做它该做的事：

restrict,port-forwarding,command="/bin/false",permitlisten="localhost:2222" ssh-ed25519 AAAA... ana@home
restrict,port-forwarding,command="/bin/false",permitopen="localhost:2222" ssh-ed25519 AAAA... ana@work
  • restrict 关掉一切（终端、转发、代理），port-forwarding 再只把隧道打开。
  • command="/bin/false" 让任何命令立刻结束：用这些密钥，跳板不能用来做别的事。
  • permitlisten="localhost:2222"：家里只能打开 2222 端口。
  • permitopen="localhost:2222"：公司只能去 2222 端口。

就算有人偷走了其中一把密钥，在跳板上也打不开终端、看不了文件，也跳不到别的地方。

3. 从家里打开隧道

在家里的电脑上：

ssh -N -R 2222:localhost:22 tunnel@jump.example.com
  • -R 2222:localhost:22：跳板的 2222 端口通到你家的 SSH（22 端口）。
  • -N：不打开终端，只保持隧道。

这个 2222 只在跳板内部（localhost）监听，从互联网上看不到，这正是我们想要的。

4. 从公司连进来

隧道打开后，在公司的电脑上：

ssh -J tunnel@jump.example.com -p 2222 ana@localhost

-J 的意思是"从这里跳过去"。这里的 localhost 是跳板的 localhost，也就是通往你家的门；ana 是你在家里电脑上的用户。

每次都打这么长很累。在公司电脑的 ~/.ssh/config 里给每台机器起个名字：

Host jump
    HostName jump.example.com
    User tunnel

Host home
    HostName localhost
    Port 2222
    User ana
    ProxyJump jump

之后只要：

ssh home

5. 让隧道不会断

家里断网或者电脑重启，隧道就没了。我们在家里的电脑上把它做成一个 systemd 服务，放在 /etc/systemd/system/jump-tunnel.service：

[Unit]
Description=Reverse tunnel to the jump host
After=network-online.target
Wants=network-online.target

[Service]
User=ana
ExecStart=/usr/bin/ssh \
    -N \
    -R 2222:localhost:22 \
    -o ServerAliveInterval=30 \
    -o ServerAliveCountMax=3 \
    -o ExitOnForwardFailure=yes \
    -o BatchMode=yes \
    tunnel@jump.example.com
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
  • ServerAliveInterval=30 和 ServerAliveCountMax=3：每 30 秒检查一次跳板有没有回应。连续三次失败就断开，由 systemd 重新打开。
  • ExitOnForwardFailure=yes：如果没能打开 2222 端口，就直接退出，而不是连着却没有隧道。
  • BatchMode=yes：如果有东西要求输入密码或确认指纹，就直接失败，而不是一直等一个永远不会来的回答。

BatchMode 只对隧道有效，也就是这个服务建立的连接。你用 ssh home 连进来时，SSH 照样会问你的密码或密钥口令。隧道真正需要的是一把没有口令的密钥，因为它自己启动时没有人在旁边输入。所以这把密钥在跳板上被限制为只能打开 2222 端口。

因此，启用之前先以 ana 手动连一次，接受跳板的指纹。然后：

sudo systemctl daemon-reload
sudo systemctl enable --now jump-tunnel

跳板上还差一个细节。家里断网时，跳板要过一阵子才发现，在这期间还会为那条死掉的连接占着 2222 端口，新的隧道就会一次又一次失败。为了让它尽快放手，在跳板的 /etc/ssh/sshd_config 里加上：

ClientAliveInterval 30
ClientAliveCountMax 3

然后用 sudo systemctl restart ssh 重启它的 SSH。这样跳板会在一分半钟内关掉死连接。

复制文件

有了上面的配置，scp 和 rsync 用 home 这个名字就会自动经过跳板：

# 把一个文件从公司传到家里
scp report.pdf home:/home/ana/

# 整个文件夹（只复制有变化的部分）
rsync -av project/ home:/home/ana/project/

在公司打开家里的服务

如果家里有一个网站跑在 8080 端口（或者一个数据库在 5432），可以用隧道把它带到公司的电脑上：

ssh -N -L 8080:localhost:8080 home

只要这条命令开着，在浏览器里打开 http://localhost:8080 就能访问家里的服务。

验证一下

在相信一件事之前，我们喜欢先确认它真的走了我们以为的路。在家里的电脑上，检查隧道是否还活着：

systemctl status jump-tunnel

应该显示 active (running)。在公司用 -v，SSH 会告诉你它在做什么：

ssh -v home

在它输出的内容里，留意这几行：

debug1: Setting implicit ProxyCommand from ProxyJump: ssh -v -W '[%h]:%p' jump
Authenticated to jump.example.com ([203.0.113.10]:22) using "publickey".
Authenticated to localhost (via proxy) using "publickey".

第一行说明它会用跳板，第二行说明已经进入跳板，第三行说明已经通过跳板进入你家（via proxy）。

你的连接是抗量子的吗？

有人可能今天录下你的加密连接，一直保存到出现能破解它的量子计算机。为此，SSH 用一种能抵抗这类计算机的方法来商定每次会话的密钥。要查看它用的是哪一种：

ssh -v home exit 2>&1 | grep 'kex: algorithm'

-v 把信息写成错误输出；2>&1 是为了让 grep 也能读到。会出现两行，每段连接一行：第二行是到你家的那段，也就是传输你数据的那段。

debug1: kex: algorithm: sntrup761x25519-sha512@openssh.com
debug1: kex: algorithm: mlkem768x25519-sha256
  • mlkem768x25519-sha256 或 sntrup761x25519-sha512@openssh.com：抗量子。你已经受到保护。
  • curve25519-sha256 或其他：今天是安全的，但防不了这种录制。公司或家里的电脑用的是 9.0 之前的 OpenSSH，请升级。

你的 ed25519 密钥不用换：这取决于 OpenSSH 的版本，而不是密钥。

如果你的 SSH 比较旧

-J 和 ProxyJump 从 OpenSSH 7.3 开始才有，permitlisten 从 7.8 开始（可以用 ssh -V 查看）。如果公司的 SSH 更旧，home 这一段就用传统写法，效果一样：

Host home
    HostName localhost
    Port 2222
    User ana
    ProxyCommand ssh -W %h:%p jump

Windows 10 和 11 已经自带 OpenSSH 客户端，也支持 -J。配置文件在 C:\Users\你的用户名\.ssh\config。

需要注意的地方

  • 不要把任何私钥复制到跳板上。用 -J 就不需要：跳板只看得到公钥。
  • 不要把 2222 开放到互联网。跳板可以用 GatewayPorts yes 把它公开，这样就不用 -J 了，但这等于把你家的 SSH 开放给全世界，正是我们想避免的。
  • 小心 -A（转发代理）。在你连接期间，跳板上任何有管理员权限的人都能使用你的密钥。用 -J 就不需要它。
  • 如果看到 remote port forwarding failed for listen port 2222，说明跳板还在为旧连接占着这个端口。在跳板上设置了 ClientAliveInterval 后，过一会儿就会自己恢复。
  • 指纹要确认两次。第一次连接时，SSH 会先让你接受跳板的指纹，再接受你家的指纹，后者显示为 [localhost]:2222。如果回答 no，会看到 Host key verification failed.
  • 跳板必须允许转发。默认是允许的，但如果有人在跳板上设置了 AllowTcpForwarding no，跳转会失败，并显示 administratively prohibited: open failed。
  • 关掉家里的密码登录。等你能用密钥登录之后，在家里电脑的 /etc/ssh/sshd_config 里设置 PasswordAuthentication no。

我们学到了什么

最直接的办法（在路由器上开端口）很多时候行不通，就算行得通，也会让你家暴露在所有人眼前。把它反过来：家里用 -R 主动连跳板，你用 -J 从这条隧道进来，跳板就只是一根什么都读不懂的管子。有了 systemd 服务和受限的 tunnel 用户，剩下的只是在任何地方输入 ssh home。先用 ssh -v home 试一下，找到那行 via proxy：看到它，你就知道自己是用正确的方式连进来的。
