Búsqueda en profundidad (DFS)

Por @danny · Tutorial

DFS (Depth-First Search, búsqueda en profundidad) es una de las formas más simples de recorrer un grafo: empiezas en un nodo y avanzas todo lo que puedes por un camino antes de volver atrás a probar otro. Es la base de un montón de algoritmos y aparece seguido en entrevistas y en problemas de programación competitiva.

La idea

Imagina que estás en un laberinto. Eliges un pasillo y lo sigues hasta el fondo. Si llegas a un callejón sin salida, regresas a la última bifurcación y pruebas otro pasillo que no hayas recorrido. Y así hasta haber visto todo.

Eso es DFS. En términos de grafos:

  1. Marca el nodo actual como visitado.
  2. Para cada vecino que todavía no visitaste, haz DFS desde ese vecino.
  3. Cuando no quedan vecinos sin visitar, vuelve al nodo anterior (esto se llama backtracking).

La marca de visitado es clave: sin ella, en un grafo con ciclos darías vueltas para siempre.

Un ejemplo paso a paso

Tomemos este grafo no dirigido con 6 nodos y estas aristas: 1-2, 1-3, 2-4, 2-5, 3-6 y 5-6. Lo guardamos como una lista de adyacencia, es decir, para cada nodo, la lista de sus vecinos:

1: 2, 3
2: 1, 4, 5
3: 1, 6
4: 2
5: 2, 6
6: 3, 5

Hagamos DFS empezando en el nodo 1, revisando los vecinos en el orden de la lista:

  1. Visitamos 1. Su primer vecino sin visitar es 2.
  2. Visitamos 2. El 1 ya está visitado, así que bajamos a 4.
  3. Visitamos 4. Su único vecino es 2, ya visitado: callejón sin salida, volvemos a 2.
  4. Desde 2 queda 5. Lo visitamos.
  5. Desde 5, el 2 ya está visitado; seguimos a 6.
  6. Desde 6 llegamos a 3. Sus vecinos (1 y 6) ya están visitados, así que volvemos hasta el inicio.

El orden de visita es 1, 2, 4, 5, 6, 3. Fíjate en un detalle: aunque 3 es vecino directo de 1, lo visitamos al final, porque DFS primero se fue a fondo por el camino de 2 y llegó a 3 desde 6. Esa es justamente la "profundidad".

El código recursivo

La forma más natural de escribir DFS es con recursión: la propia pila de llamadas se encarga de "recordar" a qué nodo volver.

Python

grafo = {
    1: [2, 3],
    2: [1, 4, 5],
    3: [1, 6],
    4: [2],
    5: [2, 6],
    6: [3, 5],
}

visitado = set()
orden = []

def dfs(nodo):
    visitado.add(nodo)
    orden.append(nodo)
    for vecino in grafo[nodo]:
        if vecino not in visitado:
            dfs(vecino)

dfs(1)
print(orden)  # [1, 2, 4, 5, 6, 3]

C++

#include <iostream>
#include <vector>
using namespace std;

vector<vector<int>> grafo;
vector<bool> visitado;

void dfs(int nodo) {
    visitado[nodo] = true;
    cout << nodo << ' ';
    for (int vecino : grafo[nodo]) {
        if (!visitado[vecino]) dfs(vecino);
    }
}

int main() {
    int n = 6;
    grafo.assign(n + 1, {});
    visitado.assign(n + 1, false);
    int aristas[][2] = {{1, 2}, {1, 3}, {2, 4}, {2, 5}, {3, 6}, {5, 6}};
    for (auto& a : aristas) {
        grafo[a[0]].push_back(a[1]);
        grafo[a[1]].push_back(a[0]);
    }
    dfs(1);  // 1 2 4 5 6 3
}

El código iterativo (con una pila)

Si el grafo es muy grande, la recursión puede reventar la pila de llamadas. En Python pasa rápido: el límite por defecto ronda las 1000 llamadas anidadas. La solución es manejar la pila nosotros mismos:

def dfs_iterativo(inicio):
    visitado = set()
    orden = []
    pila = [inicio]
    while pila:
        nodo = pila.pop()
        if nodo in visitado:
            continue
        visitado.add(nodo)
        orden.append(nodo)
        for vecino in reversed(grafo[nodo]):
            if vecino not in visitado:
                pila.append(vecino)
    return orden

print(dfs_iterativo(1))  # [1, 2, 4, 5, 6, 3]

Dos detalles: metemos los vecinos al revés (reversed) para que salgan de la pila en el mismo orden que en la versión recursiva, y marcamos el nodo como visitado al sacarlo de la pila, no al meterlo. Un nodo puede entrar más de una vez a la pila, pero solo se procesa la primera vez.

¿Qué tan rápido es?

DFS visita cada nodo una sola vez y revisa cada arista una vez por cada extremo. Con V nodos y E aristas, la complejidad es O(V + E) en tiempo y O(V) en memoria extra (el conjunto de visitados y la pila). Dicho de otra forma: es lineal en el tamaño del grafo, así que puedes usarlo sin miedo incluso con cientos de miles de nodos.

Para qué se usa

  • Saber si dos nodos están conectados: haces DFS desde uno y miras si llegaste al otro.
  • Contar componentes conexas: recorres todos los nodos y, cada vez que encuentras uno sin visitar, lanzas un DFS y sumas uno al contador.
  • Detectar ciclos: si durante el recorrido llegas a un nodo que todavía está "en curso" en la pila, hay un ciclo.
  • Orden topológico: ordenar tareas que dependen unas de otras (por ejemplo, qué cursos llevar antes que otros).
  • Mapas y cuadrículas: contar islas en una matriz, rellenar un área con color (flood fill) o resolver laberintos.

Errores comunes

  • Olvidar marcar visitados: en un grafo con ciclos el programa nunca termina.
  • Marcar tarde en la versión recursiva: marca el nodo apenas entras a dfs, antes de recorrer sus vecinos.
  • Desbordar la pila: en Python, con grafos grandes, usa la versión iterativa o sube el límite con sys.setrecursionlimit.
  • Usar DFS para el camino más corto: DFS encuentra un camino, no necesariamente el más corto. Para eso, en grafos sin pesos, se usa BFS (búsqueda en anchura).

Para cerrar

DFS es poco código y mucha utilidad: avanzar hasta el fondo, marcar lo que ya viste y volver atrás cuando no hay más camino. Escríbelo un par de veces de memoria, primero recursivo y luego con pila, y después búscalo en problemas reales.
