Búsqueda en profundidad (DFS)

Tutorial por @null_djc

Si alguna vez resolviste un problema con grafos, laberintos o mapas en una cuadrícula, seguro te cruzaste con tres letras: DFS. Es Depth-First Search, búsqueda en profundidad, y es de esas herramientas que aparecen en todos lados: en entrevistas, en Codeforces y en la mitad de los problemas donde hay que "recorrer algo".

La idea entra en una frase: avanzas todo lo que puedes por un camino y, cuando ya no hay por dónde seguir, vuelves atrás a probar otro.

La idea en un ejemplo

Piensa en un laberinto. Eliges un pasillo y lo sigues hasta el fondo. Si llegas a un callejón sin salida, vuelves a la última bifurcación y pruebas un pasillo que todavía no recorriste. Y así hasta haber visto todo.

Para no dar vueltas en círculo, vas dejando una marca en cada lugar por el que pasas. Con eso ya tienes el algoritmo completo:

  1. Marcas el nodo actual como visitado.
  2. Para cada vecino que todavía no visitaste, haces DFS desde ese vecino.
  3. Cuando no quedan vecinos sin visitar, vuelves al nodo anterior. A esto se le llama backtracking.

El grafo que vamos a usar

Tomamos un grafo no dirigido con 6 nodos y estas aristas: 1-2, 1-3, 2-4, 2-5, 3-6 y 5-6. Lo guardamos como una lista de adyacencia: para cada nodo, la lista de sus vecinos.

1: 2, 3
2: 1, 4, 5
3: 1, 6
4: 2
5: 2, 6
6: 3, 5

Arrancamos en el nodo 1 y revisamos los vecinos en el orden de la lista.

La trampa

Lo primero que pensamos fue: "empiezo en 1, después visito sus vecinos 2 y 3, y después los vecinos de ellos". Y no, eso es otro algoritmo (BFS, búsqueda en anchura). DFS no termina con los vecinos de 1 antes de seguir: apenas encuentra un vecino nuevo, se mete por ahí hasta el fondo.

Fíjate en el recorrido real:

  1. Visitamos 1. Su primer vecino sin visitar es 2: nos metemos.
  2. Visitamos 2. El 1 ya está marcado, así que bajamos a 4.
  3. Visitamos 4. Su único vecino es 2, ya marcado: callejón sin salida, volvemos a 2.
  4. Desde 2 queda 5. Lo visitamos.
  5. Desde 5, el 2 ya está marcado; seguimos a 6.
  6. Desde 6 llegamos a 3. Sus vecinos (1 y 6) ya están marcados, así que volvemos hasta el inicio.

El orden queda 1, 2, 4, 5, 6, 3. El 3 es vecino directo de 1 y aun así sale último, porque lo alcanzamos desde 6 al final del camino largo. Esa es la "profundidad".

La solución recursiva

La forma más natural de escribirlo es con recursión: la pila de llamadas se encarga sola de recordar a qué nodo volver. Las tres versiones imprimen el mismo orden que sacamos a mano.

C++

#include <iostream>
#include <vector>
using namespace std;

vector<vector<int>> grafo;
vector<bool> visitado;

void dfs(int nodo) {
    visitado[nodo] = true;
    cout << nodo << ' ';
    for (int vecino : grafo[nodo]) {
        if (!visitado[vecino]) dfs(vecino);
    }
}

int main() {
    int n = 6;
    grafo.assign(n + 1, {});
    visitado.assign(n + 1, false);
    int aristas[][2] = {{1, 2}, {1, 3}, {2, 4}, {2, 5}, {3, 6}, {5, 6}};
    for (auto& a : aristas) {
        grafo[a[0]].push_back(a[1]);
        grafo[a[1]].push_back(a[0]);
    }
    dfs(1);  // 1 2 4 5 6 3
}

Python

grafo = {

Rust

fn dfs(nodo: usize, grafo: &Vec<Vec<usize>>, visitado: &mut Vec<bool>, orden: &mut Vec<usize>) {
    visitado[nodo] = true;
    orden.push(nodo);
    for &vecino in &grafo[nodo] {
        if !visitado[vecino] {
            dfs(vecino, grafo, visitado, orden);
        }
    }
}

fn main() {
    let n = 6;
    let aristas = [(1, 2), (1, 3), (2, 4), (2, 5), (3, 6), (5, 6)];

    let mut grafo = vec![Vec::new(); n + 1];
    for &(a, b) in &aristas {
        grafo[a].push(b);
        grafo[b].push(a);
    }

    let mut visitado = vec![false; n + 1];
    let mut orden = Vec::new();
    dfs(1, &grafo, &mut visitado, &mut orden);

    println!("{:?}", orden); // [1, 2, 4, 5, 6, 3]
}

Sin recursión: con una pila

Con grafos grandes, la recursión puede reventar la pila de llamadas. En Python pasa enseguida, porque el límite por defecto ronda las 1000 llamadas anidadas. La salida es manejar la pila nosotros:

def dfs_iterativo(inicio):
    visitado = set()
    orden = []
    pila = [inicio]
    while pila:
        nodo = pila.pop()
        if nodo in visitado:
            continue
        visitado.add(nodo)
        orden.append(nodo)
        for vecino in reversed(grafo[nodo]):
            if vecino not in visitado:
                pila.append(vecino)
    return orden

print(dfs_iterativo(1))  # [1, 2, 4, 5, 6, 3]

Dos detalles que nos costaron: los vecinos se meten al revés (reversed) para que salgan de la pila en el mismo orden que en la versión recursiva, y el nodo se marca al sacarlo de la pila, no al meterlo. Un nodo puede entrar más de una vez, pero solo se procesa la primera.

¿Qué tan rápido es?

Cada nodo se visita una sola vez y cada arista se revisa una vez desde cada punta. Con V nodos y E aristas, el tiempo es O(V + E) y la memoria extra O(V). O sea, lineal: con cientos de miles de nodos entra cómodo en el límite de tiempo de cualquier juez.

Para qué sirve

  • Saber si dos nodos están conectados: haces DFS desde uno y miras si llegaste al otro.
  • Contar componentes conexas: recorres todos los nodos y, cada vez que encuentras uno sin marcar, lanzas un DFS y sumas uno al contador.
  • Detectar ciclos: si en el recorrido llegas a un nodo que todavía está "en curso", hay un ciclo.
  • Orden topológico: ordenar tareas que dependen unas de otras, como qué cursos llevar antes que otros.
  • Cuadrículas: contar islas en una matriz, rellenar un área (flood fill) o resolver laberintos.

Lo que hay que mirar con cuidado

  • Olvidarte de marcar: con un ciclo en el grafo, el programa no termina nunca.
  • Marcar tarde en la versión recursiva: marca el nodo apenas entras a dfs, antes de mirar los vecinos.
  • La pila en Python: con grafos grandes, usa la versión iterativa o sube el límite con sys.setrecursionlimit.
  • Pedirle el camino más corto: DFS encuentra un camino, no necesariamente el más corto. Para eso, en grafos sin pesos, está BFS.

Qué nos enseñó

Que DFS es poco código y mucha utilidad: avanzar hasta el fondo, marcar lo que ya viste y volver cuando no hay más camino. Y que la mejor forma de entenderlo es hacer el recorrido a mano una vez, como arriba, antes de abrir el editor. Después escríbelo de memoria, primero recursivo y después con pila, y búscalo en problemas reales: en Codeforces puedes filtrar por la etiqueta dfs and similar.
