¿Qué es Software Development?

Por @danny · Tutorial

Si estás empezando, seguro escuchaste el término mil veces: software development, desarrollo de software, "hacer programas". En palabras simples, es el proceso de crear un programa: definir qué va a hacer, diseñar cómo, escribir el código, probarlo, publicarlo y después mantenerlo. Y no, no es solo escribir código.

De la idea al programa

Todo arranca con un problema o una idea. Puede ser "quiero que mis clientes paguen por internet" o "quiero organizar mis notas". En esa etapa todavía no se escribe ni una línea de código: se habla con la gente, se anotan requisitos y se define qué tango se quiere lograr. A esto le sigue el diseño: cómo se van a ver las pantallas, cómo se estructura la información en la base de datos, qué partes se comunican con qué.

Recién ahí aparece la parte que todos imaginan: programar. Pelear con el teclado, buscar ese error que nadie sabe por qué pasa, y celebrar cuando al fin funciona. Pero ojo, ahí no termina. El software hay que probarlo antes de soltarlo, porque un bug en producción duele. Y después, mantenerlo: arreglar lo que se rompe, mejorar lo que ya hay y agregar funciones nuevas.

El ciclo de vida del software (SDLC)

A este proceso de principio a fin se le llama ciclo de vida del desarrollo de software (o SDLC). No es una religión, es solo una forma de ordenar el trabajo:

  1. Planificación: qué se va a hacer, con cuánta gente y en cuánto tiempo.
  2. Requisitos: preguntarle al cliente o al usuario qué necesita de verdad.
  3. Diseño: armar el plano: arquitectura, pantallas, base de datos.
  4. Implementación: escribir el código de verdad.
  5. Pruebas: buscar que se rompa antes de que lo hagan los usuarios.
  6. Despliegue: ponerlo a funcionar en el ambiente de producción.
  7. Mantenimiento: seguir vivo: actualizaciones, bugs, mejoras.

No todos los proyectos pasan por estas fases en este orden. A veces se empieza con un prototipo feo solo para validar la idea, y se va puliendo sobre la marcha.

Tipos de software

El software se suele dividir en dos grandes grupos. El software de sistema es el de abajo, el que sostiene todo: el sistema operativo, los controladores, las utilidades. Sin eso, nada más funciona. Y el software de aplicación es con el que interactuamos a diario: navegadores, apps de banco, juegos, herramientas de trabajo.

Si nunca lo habías visto así, piensa en capas: el sistema operativo es la base, y encima se montan las aplicaciones que usamos todos los días.

¿Cómo se organiza el trabajo?

Aquí entra el eterno debate de las metodologías. La forma clásica era el modelo en cascada: todo ordenado, una fase detrás de otra, como una línea de producción. Suena prolijo, pero si el cliente cambia de idea a mitad de proyecto (y siempre cambia), se complica.

Por eso hoy mandan las metodologías ágiles (Scrum, Kanban): se trabaja en ciclos cortos, se entrega algo funcional cada dos o tres semanas, y se ajusta según lo que diga el usuario. Y si encima el equipo mete DevOps, los despliegues se automatizan, así que lo que desarrollas llega a producción casi sin fricción.

Quién trabaja en un proyecto

Contrario a la idea de que programar es un trabajo solitario, casi siempre hay un equipo detrás:

  • Desarrolladores: frontend (lo que ves), backend (lo que no ves), full-stack (los dos).
  • Diseñador UX/UI: que el producto se entienda y se vea bien.
  • QA: los encargados de romper el software a propósito para que aguante.
  • Product Manager o analista: el puente entre el negocio y el código.
  • DevOps: que todo se despliegue y funcione sin dramas.

En equipos chicos una persona hace de todo esto a la vez. Y está bien.

Para cerrar

El desarrollo de software no es magia ni es solo sentarse a tipear. Es resolver problemas con método, rodeado de personas, y en constante aprendizaje. Si recién empiezas, no te asustes con la lista infinita de tecnologías: aprende los fundamentos, arma cosas pequeñas y equivócate rápido. Así se llega a hacer bien.
