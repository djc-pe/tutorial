¿Cómo deshacer el último commit?

Por @danny · Tutorial

Te pasó a todos: hiciste un commit y medio segundo después te diste cuenta de algo. Un mensaje que no era, un archivo que faltaba, o directamente un cambio que no querías. Tranquilo, git pensó en esto. Deshacer el último commit es de las operaciones más usadas y, con tres comandos bien entendidos, se resuelve en segundos.

Primero: dónde viven los cambios

Antes de tocar nada, recordá que en git un cambio pasa por tres lugares: el área de trabajo (tus archivos tal cual), el staging (lo que marcaste con git add) y el commit (la foto guardada en el historial). Deshacer un commit es, en el fondo, mover cosas entre esas tres zonas.

Una regla de oro antes de seguir: si el commit ya lo subiste a GitHub (git push) y trabajás con más gente, no reescribas el historial. Saltá directo a la sección de git revert al final.

El comodín: git reset

git reset mueve el puntero HEAD hacia atrás y te deja elegir qué hacer con los cambios según el modo. Con HEAD~1 le decís "volvé un commit". Los tres modos:

  • --soft: los cambios quedan en el staging, listos para volver a commitear. No perdés nada.
  • --mixed (el modo por defecto): los cambios salen del staging y quedan como archivos modificados sin agregar. Tampoco perdés nada.
  • --hard: borra todo. Los cambios del commit se descartan para siempre. Poderoso y peligroso.

Me equivoqué en el mensaje o me faltó un archivo

El caso más común. Fue tu último commit, no lo publicaste, y querés corregirlo sin ensuciar el historial. La forma más corta es git commit --amend, que reescribe el último commit:

git commit --amend -m "Mensaje corregido"
git add archivo-faltante.js
git commit --amend

¿Y si preferís rehacer el commit desde cero? Ahí entra git reset. Elegí un modo según dónde querés que queden los cambios:

git reset --soft HEAD~1

Con --soft los archivos vuelven al staging, listos para volver a commitear. Con --mixed (o sin bandera) quedan en tu área de trabajo como ediciones sin agregar:

git reset HEAD~1

En ambos casos el commit desaparece del historial pero tus cambios están a salvo.

Quiero eliminar el commit y sus cambios

Acá ya no hay vuelta atrás: --hard descarta el commit y además los cambios que viniera. Se usa así:

git reset --hard HEAD~1

Verificalo dos veces antes de ejecutarlo. Si el cambio no estaba commiteado en ningún lado (ni siquiera otra rama), se pierde. Cuando dudes, usá --soft o --mixed, que no destruyen nada.

Si el commit ya se publicó

El escenario de equipo: commiteaste, hiciste push, y ahora hay que deshacerlo. Ahí no se usa reset porque reescribir el historial rompe el repo de los demás. La herramienta correcta es git revert, que no borra nada: crea un commit nuevo que invierte los cambios del anterior.

git revert HEAD
git revert <hash-del-commit>

El historial queda limpio y transparente, y cualquiera puede ver que hubo un commit y su corrección. Es la opción segura para trabajar en equipo.
