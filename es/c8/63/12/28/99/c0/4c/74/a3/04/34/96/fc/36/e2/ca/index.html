¿Cómo deshacer el último commit?

Por @danny · Tutorial

Commiteaste, cerraste la pestaña y treinta segundos después te diste cuenta: faltó un archivo, el mensaje quedó mal o metiste un cambio que no iba. Si te suena familiar, tranquilo, es el pan de cada día, y la buena noticia es que deshacer el último commit es de las operaciones más fáciles de git; con tres o cuatro comandos bien entendidos lo resolvés en segundos.

Primero: dónde viven los cambios

Antes de meternos en los comandos conviene tener claro que en git un cambio recorre tres lugares: el área de trabajo (tus archivos tal cual), el staging (lo que marcaste con git add) y el commit (la foto guardada en el historial). Deshacer un commit no es más que mover cambios entre esas tres zonas según lo que necesites.

Una única regla de oro: si el commit ya lo publicaste con git push y trabajás con más gente, no reescribas el historial y saltá directo a la sección sobre git revert al final.

El comodín: git reset

La herramienta principal para esto es git reset: mueve el puntero HEAD hacia atrás (con HEAD~1 volvés un commit) y te deja decidir qué hacer con los cambios según el modo. Tenés tres modos disponibles:

  • --soft: vuelve el commit y deja los cambios esperando en el staging, listos para commitear de nuevo, no perdés nada.
  • --mixed (el modo por defecto): los cambios salen del staging y quedan como simples modificaciones en tu área de trabajo, tampoco perdés nada.
  • --hard: descarta el commit y sus cambios por completo, poderoso pero sin vuelta atrás.

Me equivoqué en el mensaje o me faltó un archivo

Es el caso más habitual: el commit es el último, todavía no se publicó y querés corregirlo sin ensuciar el historial. La forma más corta es git commit --amend, que reescribe el último commit, ya sea solo para arreglar el mensaje o después de agregar el archivo que faltaba:

git commit --amend -m "Mensaje corregido"
git add archivo-faltante.js
git commit --amend

Y si lo que querés es rehacer el commit desde cero para cambiar lo que incluía, entra git reset con el modo que más te sirva: usá --soft si querés que todo quede listo para commitear de nuevo:

git reset --soft HEAD~1

o --mixed si preferís que los cambios vuelvan a tu área de trabajo como ediciones pendientes:

git reset HEAD~1

En cualquiera de los dos casos el commit desaparece del historial, pero tus cambios quedan a salvo.

Quiero eliminar el commit y sus cambios

Para el caso extremo existe git reset --hard, que descarta el commit y también los cambios que traía consigo:

git reset --hard HEAD~1

Fijate dos veces antes de ejecutarlo, porque si ese cambio no está commiteado en ningún otro lado (ni siquiera en otra rama) se pierde para siempre; cuando te quede la duda, preferí --soft o --mixed, que no destruyen nada.

Si el commit ya se publicó

Esto aplica sobre todo al trabajo en equipo: ya hiciste el push y ahora te toca deshacerlo. En ese caso no usamos reset, porque reescribir el historial les rompe el repo a los demás; la herramienta correcta es git revert, que en lugar de borrar nada crea un commit nuevo que invierte los cambios del anterior:

git revert HEAD
git revert <hash-del-commit>

El historial queda limpio y transparente: cualquiera puede ver que hubo un commit y después su corrección, y por eso es la opción segura cuando el cambio ya fue compartido.
