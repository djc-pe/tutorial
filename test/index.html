Nav como script

Esta pagina no tiene el nav en el HTML. Lo agrega addnav.js al cargarse, asi que el nav queda en una sola parte del proyecto en vez de repetido en cada pagina.

Como se usa

Una sola linea, en el <head>:

<script src="/test/addnav.js" defer></script>

Eso es todo. El script pide data.json, inyecta el markup, mete nav.css y cablea el comportamiento: los drawers lateral y derecho, la busqueda por hash y el cierre con Escape.

Los datos van aparte

En addnav.js no hay ni una sola url. Todo el contenido esta en data.json: las urls del sitio, los iconos, los textos y los links de los dos menus.

Para cambiar un link se edita data.json y listo. El js solo sabe como armar el html y como hacerlo funcionar.

{
  "root": "https://www.djc.pe/",
  "story": "https://story.djc.pe/",
  "site": "https://tutorial.djc.pe/",
  "icons": { "menu": "...", "logo": "...", "user": "..." },
  "labels": { "menu": "Menu", "search": "Buscar" },
  "drawers": {
    "main": {
      "title": "DJC",
      "links": [
        { "text": "Inicio", "url": "{{root}}" }
      ]
    }
  }
}

Los {{root}}, {{story}} y {{site}} son reemplazos: si cambia la url de root en un solo lado, se actualiza en todos los links que la usen.

Agregar, quitar y agrupar links

Los links de cada menu son una lista. Para agregar o sacar uno, se edita la lista y nada mas.

Un item con { "hr": true } dibuja un separador, que sirve para dejar los grupos claros. Va en la posicion que le pongas, asi que se puede usar en el medio, al principio o al final.

"links": [
  { "text": "Inicio", "url": "{{root}}" },
  { "text": "Story", "url": "{{story}}" },

  { "hr": true },

  { "text": "Tutorial", "url": "{{site}}" },
  { "text": "Blog", "url": "{{root}}blog" }
]

Eso deja el menu en dos grupos: navegacion general arriba, y contenido del sitio abajo.

Una lista sin ningun hr se dibuja igual, como una lista corrida. Y si queda vacia, el menu aparece sin separadores colgando.

Costo de mover los datos

El json se pide por red, asi que el nav aparece un instante despues que antes. Si la peticion falla, la pagina se sigue viendo igual, solo que sin nav, y queda un aviso en la consola.

En un sitio chico con hosting estatico esa espera es de unos milisegundos, pero es el precio de tener los datos separados.

Alcance de la prueba

Todo lo de este prototipo vive en /test/: la pagina, addnav.js, data.json y nav.css. No se toco ningun archivo del resto del sitio.

nav.css es una copia de los estilos que ya estan en static/www/components/top_nav_v2/, justamente para no depender de ellos y poder medir la pagina por separado. Cuando esto se aplique al sitio real, el CSS deberia quedar en el componente compartido y no duplicado.

Un detalle de cacheo: data.json se guarda 10 minutos en el navegador. Si cambias un link, a quien ya lo tiene descargado le puede tardar esos 10 minutos en ver el cambio.

Sin el script

Si sacas esa linea, la pagina se ve igual de bien: el contenido conserva su margen, los estilos del body siguen aplicando y no queda ningun hueco raro. Lo unico que no aparece es el nav, que es justo lo esperado.

Para verlo, comentá la linea del <script> y recargá.

Migracion gradual

El script es idempotente. Si una pagina ya trae el nav escrito a mano, addnav.js detecta el #drawerOverlay y no inyecta nada, asi que se puede migrar de a una sin romper las que todavia no se tocaron.

Por eso el <script> se puede dejar puesto en todo el sitio de una vez y despues ir borrando el nav duplicado pagina por pagina.

Que trae el componente

  • Barra superior con menu, logo, buscador y cuenta.
  • Drawer izquierdo con los links del sitio.
  • Drawer derecho con iniciar sesion y registrarse.
  • Busqueda: hashea la consulta con SHA-256 y lleva a /search/q/<hash>/.
